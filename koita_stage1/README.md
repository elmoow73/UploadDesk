# KOITA 보도자료 프로그램 — 1단계

## 본문 이미지 가로 700px

‘첫 페이지 JPG 생성 (가로 700px)’은 실제 JPG 파일을 가로 700px로 리샘플링하고 원본 비율로 세로를 계산해 저장합니다(1240×1754 → 700×990). 본문 삽입 시에도 직접 선택 이미지와 내장 미리보기에 동일한 크기를 적용합니다. 기존에 크게 생성된 이미지도 다시 선택해 실행하면 본문에 들어갈 때 700px로 변환되며 원본 선택 이미지는 덮어쓰지 않습니다. 새 저장 JPG가 필요하면 생성 버튼을 다시 누르세요.

## 입력 순서 및 커서 간섭 대응

내용 자동 입력을 체크한 경우 편집기 초기화 완료 확인 → 구분·제목·공지·작성자·게시일자·공개 입력 → 본문 JPG 및 문구 작성·이미지 로딩 확인 → 첨부 목록 확인 → 기본 항목 값 재검증 → 마지막 관련사이트 입력 순서입니다. 본문·첨부가 완료되지 않으면 관련사이트를 입력하지 않습니다. 내용 자동 입력을 체크하지 않은 경우에는 기존대로 관련사이트만 입력할 수 있습니다.

제목과 관련사이트 등 텍스트 입력은 현재 커서에 키를 보내지 않고 확인된 input 요소의 값에 직접 지정한 뒤 input/change 이벤트를 발생시키고 값을 다시 읽어 확인합니다. 관련사이트 입력 전후에는 제목·작성자·게시일자·본문 텍스트·이미지가 유지되는지 확인합니다. 로컬 브라우저에서 편집기가 5ms 간격으로 포커스를 가져가는 상황에서도 입력칸과 본문이 유지됨을 검증했습니다. 자동 검사 27개 통과. 최종 저장은 누르지 않습니다.

## 첫 페이지 JPG 직접 생성 및 이미지 선택

1. HWPX 파일을 선택합니다.
2. ‘첫 페이지 JPG 생성’을 누르면 설치된 한글의 별도 자동화 인스턴스에서 원본을 열고 첫 페이지를 150dpi로 렌더링합니다. 이 PC의 한글 API는 BMP를 출력하므로 JPG로 다시 인코딩합니다. 생성 중 창은 응답하며 파일 접근 확인 창이 뜨면 사용자가 직접 허용해야 합니다.
3. 생성된 JPG는 `koita_stage1/generated/`에 저장되고 본문 이미지로 자동 선택됩니다. 데모데이 실제 문서에서 1240×1754 이미지 생성과 원본 해시 불변을 검증했습니다.
4. 별도로 준비한 첫 페이지 이미지가 있으면 ‘JPG·PNG 직접 선택’을 사용합니다. HWPX 파일을 다시 선택하면 기존 이미지 선택은 지워집니다.
5. ‘등록 페이지 도착 후 내용 자동 입력’을 체크하고 실행합니다. 선택/생성된 이미지를 우선 사용합니다. 이미지 미지정 시 내장 미리보기를 사용하며, 그것도 없으면 한글에서 자동 생성합니다. 온라인 날짜 추출과 원본 HWPX 첨부는 기존대로 진행하고 최종 저장은 누르지 않습니다.

한글 데스크톱 프로그램과 `pywin32`가 필요합니다(`requirements.txt`에 포함). 외부 변환 서비스로 파일을 보내지 않습니다. 원본 문서는 저장하지 않으며 한글 파일 보안 확인을 우회하지 않습니다. 변환이 120초를 넘으면 오류를 표시합니다. 이때 한글의 확인 창이나 변환용 창이 남아 있으면 직접 확인/종료하세요. 생성 이미지 및 수동 이미지 선택을 포함한 자동 검사 26개와 실제 한글 렌더링 테스트를 통과했습니다.

## 날짜 표기 차이 대응

온라인 날짜의 일자 뒤 마침표는 선택으로 인식합니다. `2026. 10. 20.(화)`와 `2026. 10. 21(수)`를 모두 지원하며, 지면 날짜를 대신 사용하지 않습니다. 전각 기호·일부 공백·제로폭 문자도 정규화합니다. 실제 데모데이 파일에서 `2026-10-21` 추출을 검증했습니다. 서로 다른 온라인 날짜가 여러 개면 추측하지 않고 중단합니다.

데모데이 HWPX에는 `Preview/PrvText.txt`만 있고 첫 페이지 이미지가 없습니다. 현재는 위의 한글 렌더링 경로로 첫 페이지 이미지를 생성할 수 있습니다.

## 관련사이트 선택

첫 화면에서 선택 항목인 ‘관련사이트 선택’을 누릅니다. `C:\Users\21017\Desktop\MyBrain\News\koita_news.sqlite`의 `news` 테이블을 읽기 전용으로 조회하고 날짜·출처·유형·제목·URL과 체크박스를 보여줍니다. 같은 폴더의 JSON·CSV는 중복 수록하지 않습니다. 최신 날짜부터 표시하며 검색과 DB 새로고침을 지원합니다. 체크 후 ‘선택 적용’을 누르면 메인 화면에 선택 건수가 표시됩니다. 체크를 모두 해제해 적용하면 관련사이트 없이 진행합니다. 취소하면 기존 선택을 유지합니다. 목록은 창을 열 때와 새로고침 때 다시 읽습니다. 선택값은 이번 실행의 메모리에만 보관합니다.

등록 페이지 도착 후, 선택한 기사 수만큼 관련사이트 행을 확보합니다. 3개 선택 시 기본 1행에 추가 버튼을 2번 눌러 3행을 만듭니다. `title → relSiteTitle(제목)`, `url → relSiteUrl(URL)`, `press → relSiteMedia(출처)` 순서로 입력하고 값을 검증합니다. 기존에 값이 들어 있는 관련사이트는 덮어쓰지 않습니다. 관련사이트는 본문 자동 입력 체크 여부와 별개로 선택한 경우 입력합니다. 기존 본문 자동 입력 체크를 해제한 상태에서 관련사이트만 시험할 수 있습니다. 최종 저장은 누르지 않습니다.

검증: 자동 검사 15개 통과. 제공된 실제 등록 폼 HTML을 사용하는 로컬 브라우저에서 실제 DB 기사 3개 선택 → 추가 2회 → 관련사이트 3행의 값 검증을 통과했습니다. 로컬 검사에서는 DB만 읽으며 KOITA 서버에 접속하거나 게시물을 등록하지 않습니다. 로그인 후 실제 사이트 연동은 프로그램에서 확인해야 합니다.

## 오류 복구: 등록 페이지 이동과 입력 분리

기본 실행은 이전처럼 등록 페이지를 여는 데서 멈춥니다. GUI의 ‘등록 페이지 도착 후 내용 자동 입력’을 체크한 경우에만 준비한 내용을 입력합니다. 파일·제목은 계속 필수입니다. 메뉴 이동이 실패하면 등록 페이지를 반환하지 않으며 그 단계의 오류를 그대로 유지합니다. 실패한 창에 입력 함수를 실행해 ‘등록 페이지가 아닙니다’로 원래 오류를 덮어쓰던 문제를 수정했습니다. 자동 입력 모드도 최종 저장은 누르지 않습니다.

## 현재 기능: 등록 폼 채우기

ID·비밀번호·HWPX 파일·보도자료 제목은 모두 필수입니다. 실행 버튼은 ‘로그인 후 보도자료 내용 채우기’입니다. 기존 안내 중 파일·제목이 선택이라는 설명은 이전 단계 기준이며 현재 적용되지 않습니다.

| 항목 | 입력값 / 확인한 요소 |
|---|---|
| 구분 | 보도자료 (`#code`, `004002000`) |
| 제목 | GUI 입력값 (`input[name=title]`) |
| 공지 | 아니오 (`topYn=N`) |
| 작성자 | 이승현 (`userNm`) |
| 게시일자 | HWPX `(온라인)` 날짜 (`#vwRegDt`), 예시 2026-10-20 |
| 공개 | 공개 (`vwYn=Y`) |
| 내용 | HWPX 내장 첫 페이지 미리보기를 JPG로 변환 + 줄바꿈된 안내 문구 |
| 첨부 | 원본 HWPX (`#coa_html_upload`) |

이미지는 HWPX에 저장된 첫 페이지 미리보기(예시 724×1024)를 사용합니다. 새로 고해상도 조판하는 방식은 아닙니다. `CrossEditor.SetBodyValue/GetBodyValue`로 JPEG data URI와 안내 문구를 넣고 편집기 반환값과 실제 이미지 로딩을 확인합니다. 실제 사이트가 data URI를 차단하거나 변환하면 중단합니다. 최종 저장 후 서버에서의 보존은 이번 범위에서 검증하지 않았습니다.

첨부는 원본을 선택한 뒤 `#coa_view_box` 목록에 원본 파일명이 표시되는지 확인합니다. 이는 첨부 대기 목록 확인이며 서버 전송 완료를 뜻하지 않습니다. 제공된 HTML의 허용 확장자 안내에는 HWPX가 없으므로 사이트에서 거부할 수 있습니다. 검사를 우회하거나 파일 확장자를 변경하지 않습니다. 최종 게시물 저장은 실행하지 않습니다.

테스트: `test_stage1.py`의 11개 검사와 `test_registration_browser.py`의 로컬 브라우저 폼 검사. 예시 HWPX에서 날짜 추출 및 첫 페이지 JPG 변환을 검증했습니다. 실제 로그인 상태의 나모 편집기·첨부 서버는 사용자가 실행해 확인해야 합니다.

## 등록 페이지 열기 테스트 추가

관리자 사이드바는 같은 주소를 여러 메뉴가 공유하므로 주소만으로 클릭하지 않습니다. 제공된 `lft_sub_menu_ul → lv1_2 → sec_ul → tir_ul` 계층과 표시 이름으로 `게시판 관리 → 산기협 → 언론홍보 → 등록`을 구분합니다. `test_admin_dom.py`는 제공된 메뉴 구조의 로컬 HTML로 선택자 중복 문제를 검증하며 로그인이나 외부 접속을 하지 않습니다.

버튼을 누르면 로그인 시도 후 사용자 제공 HTML의 `Koita관리자` 메뉴가 표시되기를 최대 30초 기다립니다. 메뉴가 표시되면 클릭하여 새 창을 받고, `게시판 관리 → 산기협 → 등록`을 순서대로 클릭합니다. 마지막 주소가 `/admmgr/board/commBoardPressRegist.do`인지 확인한 후 멈춥니다. 내용 입력, 파일 업로드, 최종 저장은 하지 않습니다. SSO URL의 사용자 ID는 하드코딩하지 않고 실제 메뉴의 동작을 그대로 사용합니다.

관리자 메뉴가 숨겨져 있으면 사용자 제공 HTML의 마이오피스 상위 메뉴(`li[name="topmenu_li"][id="javamail/index_javamail.aspx"]`)에 마우스를 올립니다. 그래도 표시되지 않으면 `span.icon_menu.top_myOffice` 아이콘을 한 번 클릭하고 관리자 메뉴가 표시되는지 다시 확인합니다. 반복 클릭으로 메뉴를 접지 않습니다. 추가 인증이나 화면 구조 변경으로 진행하지 못하면 상태를 표시합니다. 테스트는 모의 브라우저의 메뉴 순서와 중단 범위, 다른 관리자 주소 차단을 검증했습니다. 실제 계정으로 전체 경로를 실행한 검증은 사용자의 PC에서 필요합니다.

Windows용 PySide6 GUI입니다. ID, 마스킹된 비밀번호, HWPX 파일 선택, 보도자료 제목과 로그인 테스트 버튼을 제공합니다. ID와 비밀번호만 필수입니다. 파일과 제목은 메모리에만 유지하고 읽거나 전송하지 않습니다.

## 실행

Python 3.11 이상과 설치된 Chrome 또는 Edge가 필요합니다. 이 폴더에서 명령 프롬프트를 열어 실행하세요.

```bat
py -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python app.py
```

Playwright의 별도 Chromium 다운로드는 필요하지 않습니다. 설치된 Chrome을 먼저 시도하고 실행되지 않으면 Edge를 사용합니다. 회사 보안 정책이 자동화를 차단하면 관리자에게 확인하세요.

## 실제 사이트 확인 상태

2026-10-22 설치된 브라우저를 Playwright로 열어 실제 로그인 DOM을 확인했습니다. ID는 `#uid`, 비밀번호는 `#upw`입니다. 사용자 제공 HTML에 따라 화면에 표시되는 로그인 라벨 `label[for="LoginButton"]`을 클릭합니다. 현재 버튼은 https://gw.koita.or.kr/ 을 열고 이 요소를 확인한 후 자동 입력 및 로그인 시도를 1회 수행합니다. 계정이 제공되지 않아 실제 인증과 인증 후 성공·실패 표시는 확인하지 못했습니다. 따라서 현재는 ‘로그인 시도 완료 · 성공 여부 미검증’으로 표시하며 브라우저에서 직접 결과를 확인해야 합니다. 로그인 버튼을 누른 사실을 성공으로 간주하지 않습니다.

다음 단계는 사용자 PC에서 로그인 결과 화면을 함께 확인하는 것입니다. 사용자가 로그인한 후 인증된 화면에만 나타나는 성공 표시를 확인해야 합니다. 비밀번호, 쿠키, 토큰, 네트워크 요청 본문을 공유하지 마세요. 성공 표시가 로그인 전에도 존재하면 사용할 수 없습니다.

입력 선택자는 `login_selectors.json`에 이미 반영했습니다. 인증된 화면에서 확인한 CSS 선택자만 `success`에 지정하면 성공 자동 판정이 활성화됩니다. iframe이 있을 때만 `frame_selector`를 지정합니다. 실패 표시를 확인한 경우 `failure`도 지정합니다. `evidence`에 확인 날짜와 화면 설명(비밀정보 제외)을 적습니다. 변경 후 실제 계정으로 1회 테스트하여 성공·실패 판정을 확인하세요. 설정값을 추측하여 채우면 안 됩니다. `verified`를 false로 설정하면 자동 입력을 중지하고 화면 확인 안내만 표시합니다.

설정 완료 후에도 화면 요소가 유일하고 표시되어 있으며 로그인 페이지가 지정된 HTTPS 호스트일 때만 입력합니다. 자동 재시도는 하지 않습니다. 성공 요소를 확인하지 못하면 ‘결과 확인 불가’로 표시합니다. 추가 인증은 사용자가 직접 수행하며 인증서 경고·CAPTCHA·MFA를 우회하지 않습니다. SSO로 다른 호스트로 이동하면 자동 입력을 중단하고 별도 확인이 필요합니다.

브라우저는 결과 확인을 위해 열어 둡니다. ‘테스트 종료 / 브라우저 닫기’나 창 닫기로 종료하면 임시 컨텍스트도 닫힙니다. 종료 요청은 진행 중인 요청의 제한 시간(최대 약 30초)을 기다릴 수 있습니다.

## 보안과 범위

비밀번호는 실행 중 입력·전송에 필요한 메모리에서만 사용하고 GUI에서는 실행 직후 지웁니다. 비밀번호 저장, 로그, 스크린샷, 추적, 세션 내보내기 기능은 없습니다. Python 문자열을 물리적으로 덮어쓰는 보장은 없습니다. 개인 브라우저 프로필 대신 새 임시 컨텍스트를 사용합니다. 게시판 이동, 게시물 등록, HWPX 변환·분석·업로드는 구현하지 않았습니다.

## 테스트

```bat
.venv\Scripts\python -m unittest discover -v
```

목적지 검사, 미확인 선택자일 때 자동 입력 금지, 비밀번호 마스킹과 필수 입력 검사를 포함합니다. 실제 인증 검증을 대체하지 않습니다.
